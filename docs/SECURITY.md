# Безопасность Career Quest

## Что защищено и как

| Угроза | Мера |
| --- | --- |
| Подбор пароля | scrypt (N=2¹⁴, r=8, p=1, соль 16 байт); блокировка учётной записи после 5 ошибок на 15 минут; не более 30 попыток входа с IP за 15 минут; одинаковый ответ для неизвестной почты и неверного пароля |
| Слабые пароли | Не короче 10 символов, буквы и цифры, проверка по списку распространённых; временный пароль от HR обязательно меняется при первом входе |
| Кража сессии | Случайный 256-битный токен в cookie `httpOnly`, `SameSite=Strict`, `Secure` при HTTPS; в базе только SHA-256 токена; срок 12 ч и 2 ч простоя; выход, сброс пароля и отключение отзывают сессии |
| CSRF | SameSite=Strict и проверка `Origin`/`Referer` для изменяющих запросов с cookie |
| XSS, кликджекинг | React экранирует вывод; CSP `default-src 'self'` без сторонних скриптов и шрифтов; `X-Frame-Options: DENY`, `frame-ancestors 'none'`; токен сессии недоступен JavaScript |
| Доступ к чужим данным | Роли проверяются на сервере для каждого маршрута; сотрудник видит только себя; каждый просмотр профиля HR пишется в журнал |
| Накрутка навыков | В продакшне выполнение подтверждает HR; повышение грейда — только решением HR с проверкой обязательных требований |
| Повтор и гонки запросов | `Idempotency-Key` для изменений; все записи сериализуются в базе; запись сотрудника меняет только его строки |
| Порча данных импортом | Проверка всего набора до записи, режим «проверить без записи», автоматический снимок до импорта и восстановление |
| Большие запросы | Лимит тела: 1 МБ для JSON, 22 МБ для импорта (5 МБ на файл); Caddy — 25 МБ |
| Утечка через ошибки | Единый формат ошибок без трассировок; `Server` не раскрывается; Swagger выключен в продакшне |
| Перерасход GPT | Ключ только на сервере, лимит вызовов в сутки на пользователя, тайм-аут 7 с, обезличенные признаки |
| Прослушивание | HTTPS через Caddy, HSTS; база в изолированной сети контейнеров |
| Повышение привилегий в контейнере | Непривилегированный пользователь, read-only файловая система, `no-new-privileges` |
| Расследование | Журнал действий (кто, что, когда, IP) и JSON-логи запросов с `X-Request-ID` |

## Чек-лист перед запуском

- [ ] Сервер и копии — в дата-центре на территории РК; копии шифруются и хранятся вне сервера.
- [ ] `CAREER_QUEST_ENV=production` (задано в `compose.prod.yaml`), HTTPS работает, HTTP перенаправляется.
- [ ] `POSTGRES_PASSWORD` случайный и длинный; `.env` с правами `600`, не в git.
- [ ] Первый HR сменил пароль; `CAREER_QUEST_BOOTSTRAP_HR_PASSWORD` удалён из `.env`.
- [ ] Демо-набор заменён реальными данными; служебные `smoke-*` учётные записи отсутствуют.
- [ ] `CAREER_QUEST_FORWARDED_ALLOW_IPS` указывает только на ваш обратный прокси.
- [ ] Тексты согласия и политики утверждены юристом, версия `CAREER_QUEST_CONSENT_VERSION` обновлена.
- [ ] Настроены оповещения (`/api/ready`, 5xx, копии) и проверено восстановление из копии.
- [ ] Если включён GPT — оценена допустимость передачи обезличенных признаков поставщику.

## Известные ограничения

- Нет SSO/LDAP и второго фактора. Для крупной организации рекомендуется вход через
  корпоративный IdP (OIDC/SAML) — точка расширения: `backend/api/auth.py`.
- Ограничение частоты входа хранится в памяти процесса (при нескольких процессах
  лимит фактически умножается); блокировка учётной записи — в базе и общая.
- CSP разрешает `style-src 'unsafe-inline'` — этого требует библиотека графиков.
- Временные пароли передаёт HR; почтовой доставки и самостоятельного
  восстановления пароля нет.
- Шифрование отдельных полей в базе не используется — полагайтесь на шифрование
  диска сервера и копий.
